# OpenWebUI v0.11.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade OpenWebUI from v0.9.6 to v0.11.0 on sweetpaintedlady, add a self-hosted SearXNG search engine, switch to env-authoritative config (`ENABLE_PERSISTENT_CONFIG=False`), and enable Sub-agents + Automations with conservative cost guardrails — all as code in composeyourself.

**Architecture:** The sweetpaintedlady Docker Compose overlay gains one new service (`searxng`, internal-only on `cys-service`). The `openwebui` service gets a version bump plus a block of env vars that are authoritative on every boot (no more DB-stored config drifting). The existing `generate_config.sh` config.json copy is retired (replaced by `DEFAULT_MODELS` env) and gains a SearXNG settings copy step (mirroring the config.json pattern).

**Tech Stack:** Docker Compose, OpenWebUI v0.11.0, SearXNG (Granian-based image), generate_config.sh (bash), seed-openwebui.sh (bash + curl).

## Global Constraints

- **Never run `docker compose up` from this workspace checkout.** Deploys happen on the target host (`/opt/docker/composeyourself`, as `dockerops`) via `./update.sh sweetpaintedlady` or `./restart.sh sweetpaintedlady`. The only local sanity check is `docker compose -f docker-compose.yml -f docker-compose.sweetpaintedlady.yml config` (validates YAML + interpolation).
- **Image pins are explicit.** OpenWebUI: `v0.11.0`. SearXNG: `2026.8.17-374939b88`. No `:latest` in committed compose files.
- **Config-as-code.** All OWUI settings are env vars in the committed compose file. `ENABLE_PERSISTENT_CONFIG=False` means env wins every boot; Admin UI changes are session-only and revert on restart. This is intentional and documented.
- **SearXNG is internal-only.** No host port. Reachable at `http://searxng:8080` from the `cys-service` network. Not exposed via Caddy/Authelia.
- **`.env` is never committed.** No new secrets are needed for D1 (SearXNG has no API key; the secret_key is auto-generated by the container entrypoint).

- [ ] **Step 1: Add the searxng service**

Insert the following service block after the `openwebui` service block (after line 89, before the `# Caddy` comment at line 91):

```yaml

  # SearXNG - Internal web search engine for OpenWebUI
  #
  # Internal-only on cys-service (no host port). OpenWebUI reaches it at
  # http://searxng:8080/search?q=<query>. Config is seeded from
  # services/searxng-config/settings.yml by generate_config.sh.
  #
  # The container entrypoint auto-generates a random secret_key (replacing the
  # "ultrasecretkey" placeholder in settings.yml) on first boot. No valkey
  # service needed — limiter and valkey.url default to false in our settings.
  searxng:
    image: docker.io/searxng/searxng:2026.8.17-374939b88
    container_name: searxng
    restart: unless-stopped
    logging: *default-logging
    expose:
      - "8080"
    volumes:
      - ./services/searxng/core-config:/etc/searxng:Z
      - searxng_data:/var/cache/searxng
    deploy:
      resources:
        limits:
          memory: 256M
    networks:
      - cys-service
```

  #
  # Config is fully env-authoritative (ENABLE_PERSISTENT_CONFIG=False): env vars
  # win on every boot; Admin UI changes are session-only and revert on restart.
  # This eliminates the PersistentConfig gotcha that caused the original web

  # Web search: SearXNG (internal-only service, see below). Agentic search in

  # Three switches: global engine (env), capability (DEFAULT_MODEL_METADATA),
  # default feature (DEFAULT_MODEL_METADATA defaultFeatureIds).
  #
  # Sub-agents: delegate_task builtin tool, foreground + background. Cost
  # guardrails: 5 concurrent, 3 background, 10 iterations per sub-agent.

  # Automations: RRULE-scheduled prompts. Process-bound (restart kills a
  # running automation); durable scheduling is D2's n8n job.
